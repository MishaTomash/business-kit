# SEO-план klitynka.online

Етап 1: аудит без змін у коді. Дата: 10 жовтня 2026.

Мета: щоб сайт виходив у Google на запити людей, які шукають гру в Telegram під ключ, запуск гри в Telegram Mini App, заробіток на Telegram Stars, а для Слововира ще й кросворди українською. Перше місце ніхто не гарантує. Задача цього плану інша: прибрати технічні перешкоди, вибрати реалістичні запити й зробити сторінки корисними.

Як перевірялось. Живий сайт я дивилась через Chrome 10.10.2026: статуси відповідей, редиректи, заголовки сервера, sitemap.xml і robots.txt. Згенерований HTML я дивилась у свіжій збірці поточного `main` (`npm run build` і `npm test` зелені). JSON-LD я перевірила в Chromium із точною CSP із CLAUDE.md. Пошукову видачу я дивилась через веб-пошук. Він не повністю збігається з Google, тому висновки про конкурентів орієнтовні.

## 1. Технічний стан

### Що вже добре

- Кожна сторінка зібрана в готовий HTML (prerender), тому Google бачить текст без виконання JS.
- У кожної сторінки свої `<title>`, description, canonical, повний набір Open Graph (картинка 1200×630, `og:locale uk_UA`) і `twitter:card`.
- `<html lang="uk">`.
- Редиректи працюють правильно: `http://` веде на `https://`, а `www.klitynka.online` веде на `klitynka.online` (перевірено для http і https).
- `robots.txt` дозволяє все й вказує на sitemap. Sitemap містить лише 5 сторінок, які треба індексувати.
- Заглушки ігор мають `noindex` і не потрапляють у sitemap. 404.html теж має `noindex`.
- На кожній сторінці рівно один h1, рівні заголовків не пропускаються.
- Тегів `<img>` на сторінках немає, тому проблем з alt теж немає. Декоративні SVG мають `aria-hidden`.
- Сервер віддає gzip, `/assets/` кешується на рік, HTML має `no-cache`. Заголовки безпеки (CSP, X-Frame-Options, nosniff, Referrer-Policy) на місці.
- Швидкість. Lighthouse з етапу S7 (мобільний режим, CPU ×4, gzip): головна 100 балів, LCP 1,3 с, CLS 0,022; каталог LCP 1,6 с; Слововир LCP 1,4 с. JS важить 26 КБ у gzip.

### Що зламано

**1. Canonical показує на адресу з редиректом (критично).**
nginx відповідає на `/games` редиректом 301 на `/games/`. Так само працюють `/games/slovovyr`, `/offer` і `/privacy`. Причина в правилі `try_files $uri $uri/ /index.html`: коли є папка `games/`, nginx додає слеш. При цьому canonical, sitemap і всі внутрішні посилання сайту ведуть на адресу без слеша.
Наслідок: 4 з 5 адрес у sitemap віддають редирект, а canonical сторінки `/games/` показує на `/games`, яка знову веде на `/games/`. Google отримує суперечливий сигнал. У Search Console ці адреси, найімовірніше, з'являться як «Сторінка з переадресацією», і Google сам вибиратиме канонічну адресу. Крім того, кожен клік по внутрішньому посиланню проходить через зайвий 301.
Рішення через nginx: адреса без слеша має віддаватися одразу зі статусом 200, а адреса зі слешем має вести на неї. Текст для nginx наведено нижче.

**2. М'який 404 (критично).**
Невідома адреса, наприклад `/nema-takoi` чи `/games/nema`, отримує головну сторінку зі статусом 200 і canonical на `/`. Без JS людина бачить головну, а 404 показує лише JS. Google таке або позначає як «М'який 404», або вважає ці адреси дублями головної. Будь-яке криве посилання на сайт створює ще один дубль.
Рішення через nginx: віддавати `404.html` зі статусом 404. Усі справжні сторінки зібрані prerender, тому запасний `/index.html` більше не потрібен. Старі hash-адреси (`#/p/...`) живуть на `/`, тому їх це не зачепить.
Дрібниця в коді: у `404.html` стоїть `canonical` на `https://klitynka.online/404`, якої не існує. Сторінка з `noindex` не повинна мати canonical. Це виправлення для `vite.config.ts`.

**3. Немає HSTS (низький пріоритет).**
Сервер не віддає `Strict-Transport-Security`. На позиції це майже не впливає, але це звичайна практика для https-сайту.

### Тексти для nginx (застосовуєте ви)

Пункти 1 і 2 закриває одна зміна в `location /`. Запасний `/index.html` прибирається, а `404.html` стає справжньою сторінкою 404:

```nginx
    # HTML і решта
    location / {
        # /games/ → /games (одна канонічна адреса без слеша; корінь «/» не чіпається)
        rewrite ^/(.+)/$ /$1 permanent;
        # /games віддається з games/index.html одразу, без редиректу; невідома адреса → 404
        try_files $uri $uri/index.html =404;
        add_header Cache-Control "no-cache" always;
        include /etc/nginx/snippets/business-kit-security.conf;
    }

    error_page 404 /404.html;
    location = /404.html {
        internal;
        add_header Cache-Control "no-cache" always;
        include /etc/nginx/snippets/business-kit-security.conf;
    }
```

Обидва блоки ставляться в `server { ... }` з `listen 443`, який створив certbot. Блок `/assets/` лишається як є.

Для пункту 3 у `/etc/nginx/snippets/business-kit-security.conf` додається рядок:

```nginx
add_header Strict-Transport-Security "max-age=31536000" always;
```

Попутно можна стискати й sitemap: у `gzip_types` дописати `application/xml text/plain`.

Перевірка після `sudo nginx -t && sudo systemctl reload nginx`:

```bash
curl -sI https://klitynka.online/games          # 200, без Location
curl -sI https://klitynka.online/games/         # 301, Location: /games
curl -sI https://klitynka.online/games/slovovyr # 200
curl -sI https://klitynka.online/nema-takoi     # 404
curl -sI https://klitynka.online/games/nema     # 404
curl -sI https://klitynka.online/               # 200, є strict-transport-security
curl -sI --http2 https://klitynka.online/ | head -1   # заодно видно, чи ввімкнено HTTP/2
```

Після цього в Search Console варто натиснути «Перевірити URL» для `/games` і `/games/slovovyr` і попросити індексування.

### Структура заголовків h1–h3

- h1 головної — гасло «Гра у вашому Telegram. Зірки — на вашому рахунку.». У ньому немає «під ключ» чи «Mini App», але title це компенсує. Міняти гасло заради SEO я не пропоную.
- У футері кожної сторінки є три h2: «Сайт», «Документи», «Зв'язок». Вони розмивають структуру сторінки, бо це навігація, а не розділи змісту. Їх можна замінити на звичайний підпис без заголовка (низький пріоритет).
- Решта структури логічна.

### Внутрішні посилання

- Головна не посилається на `/games/slovovyr`, хоча це єдина гра, що працює, і єдина сторінка під запити про кросворди. Зараз до неї ведуть лише каталог і чіпи жанрів.
- Сторінка Слововира посилається лише на каталог (крихти) і на футер.
- Чіпи жанрів створюють адреси `/games?genre=slova`. Canonical у них показує на `/games`, тому дублів це не створює.
- Усі внутрішні посилання зараз проходять через 301. Зміна nginx з пункту 1 це прибере.

### Open Graph

Повний набір на всіх сторінках, картинки існують, `og:image:alt` заповнений. Змін не потрібно.

### lastmod у sitemap

`lastmod` немає. Google використовує його лише тоді, коли дата правдива. Дата збірки не підходить, бо вона змінюється при кожному деплої, навіть коли зміст той самий. Чесний варіант: для оферти й політики брати дату редакції з тексту, а для інших сторінок вести дату останньої змістовної зміни в даних (`src/data/pages.ts`).

### Schema.org (JSON-LD)

Розмітки немає.
CSP її не блокує. `<script type="application/ld+json">` — це блок даних, браузер його не виконує, і `script-src 'self'` на нього не діє. Я перевірила це в Chromium із точною CSP сайту: порушень у консолі немає, а JSON читається.
Але CLAUDE.md забороняє inline-скрипти, а формально це тег `<script>`. Тому потрібне ваше рішення. Варіант без тегу `<script>` — розмітка Microdata атрибутами в HTML, але її довше підтримувати.

Що чесно можна розмітити:
- головна: `Organization` (назва, адреса сайту, логотип, контакт у Telegram) і `WebSite`;
- сторінки гри: `BreadcrumbList` (Каталог → Слововир);
- оферта: нічого.

Чого не робити: `AggregateRating` і `Review` без справжніх відгуків. `FAQPage` дозволена, але з 2023 року Google показує FAQ-розширення лише сайтам державних і медичних організацій, тож для нас вона нічого не дасть.

### Швидкість і Core Web Vitals

Тут проблем немає (цифри вище). Польових даних у звіті «Основні веб-показники» може не бути тижнями: Google показує їх лише тоді, коли з Chrome набирається достатньо відвідувань. Повідомлення «недостатньо даних» для нового сайту нормальне.

## 3. Прогалини в змісті

Нові маршрути додаються лише після вашої згоди. Кожна пропозиція нижче має відповідати на справжнє питання. Якщо сторінці нема чого сказати понад те, що вже є на сайті, вона не потрібна.

1. **Як вивести Telegram Stars на картку** (`/guides/telegram-stars`). Закриває запити «як вивести зірки Telegram», «Telegram Stars на картку». Корисно чесно: 21 день очікування, мінімум 1 000, шлях Fragment → TON → гривні, приблизна виплата $0,013 за зірку й комісії. Ви проходили це самі. Умова: посилання на офіційні джерела, дата перевірки, оновлення при зміні правил. Це найсильніша пропозиція.
2. **Як запустити гру в Telegram** (`/guides/zapusk-hry`). Закриває «як створити гру в Telegram», «Telegram Mini App гра». Покроково: BotFather, Mini App, оплата зірками, що з цього можна зробити самому і що робимо ми. Чесно, якщо описати і самостійний шлях, а не лише продавати.
3. **Готова гра чи розробка з нуля** (`/guides/hotova-chy-rozrobka`). Закриває «розробка Telegram Mini App ціна». Тут легко вийти у воду, тому лише з фактами: строки, з чого складається вартість, хто тримає сервер, кому належить бот. Чужих цін без джерела не наводити.
4. **Слововир для гравців.** Зараз сторінка Слововира продає гру власникам. Людина, яка шукає «кросворди українською», хоче пограти, а потрапляє на ціну запуску. Варіанти: блок «Як грати» з механіками (дані вже є в `games.ts` → `mechanics`, `demo`) або окрема сторінка для гравців. Це рішення ваше.
5. **Сховані відповіді FAQ.** «Як швидко відповідає підтримка?» і «Чи можна замовити свою гру?» прямо відповідають на питання покупців. Коли відповіді з'являться, це корисний текст без нових сторінок.

Чого не робити: окремі сторінки під кожне формулювання запиту (це дорвеї), сторінки міст, англійську версію до появи англомовного продукту.

## 4. Позасайтова частина (робите ви)

### Bing Webmaster Tools

1. Відкрийте bing.com/webmasters і увійдіть через акаунт Microsoft або Google.
2. Виберіть «Import from Google Search Console» — Bing підтягне сайт і sitemap без DNS-записів.
3. Перевірте в Sitemaps, що є `https://klitynka.online/sitemap.xml`.
4. У URL Inspection перевірте `/` і `/games/slovovyr`.
5. Необов'язково: IndexNow (миттєве повідомлення Bing про зміни). Для цього потрібен файл-ключ у `public/`, тобто окремий етап у коді.

### Перші чесні посилання

1. **Сам Слововир.** Опис бота, кнопка меню або розділ «Про гру» з посиланням «Хочу таку гру → klitynka.online». Це найприродніше посилання, і його бачать гравці.
2. **Telegram Apps Center** (каталог Mini App). Подайте Слововир як гру; на сторінці гри буде посилання на розробника.
3. **GitHub-список Telegram Mini Apps** (`telesearch/Telegram-Mini-Apps-List`): pull request зі Слововиром.
4. **Ваші профілі**: сайт TomashLabs, GitHub, Freelancehunt (портфоліо з посиланням на сайт і на Слововир).
5. **DOU.ua.** Справжня стаття від розробника, наприклад про економіку Telegram Stars чи про те, як влаштований Слововир, з одним посиланням на сайт. Реклама там не пройде, корисна стаття пройде.
6. **Ваш Telegram-канал і профільні чати розробників ботів.** Розповідь про запуск, а не розсилка посилань.

Не робити: купувати посилання, масово реєструватися в каталогах сайтів, обмінюватися посиланнями.
