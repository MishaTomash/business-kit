# Як додати гру на сайт

Ігри сайту приходять з платформи. Тексти, ціни, статуси й посилання «Замовити» живуть у репозиторії
klitynka-platform, у файлі `content/site/games.json`. Сайт читає їх з файлу `src/data/games.generated.json`.
Руками в сайті задається лише вигляд гри: колір і жанр генетичного відбитка (`SITE` у `src/data/games.ts`).

З цих даних сайт сам будує картку в каталозі `/games` і фільтр жанрів. Він також оновлює лічильник на
головній і збирає сторінку `/games/<id>` з калькулятором, планом і карткою покупки. Кожна сторінка отримує
окремий HTML з власними `<title>`, описом і прев'ю посилання.

---

## 1. Додати гру

1. **У платформі.** Додайте гру в `content/site/games.json` репозиторію klitynka-platform (для справжньої
   гри це робить агент нової гри за `docs/ADD-GAME.md` платформи). Там же виконайте:

   ```
   npm run export:games
   ```

2. **Скопіюйте файл.** `export/games.json` з платформи покладіть у сайт як `src/data/games.generated.json`.
3. **Вигляд на сайті.** Додайте гру в `SITE` у `src/data/games.ts`: жанр і колір відбитка, для гри, що
   працює, ще й `searchTitle` (заголовок для пошуку, до 60 символів). Без цього запису збірка зупиниться
   й назве гру.
4. **Перевірте** (`npm run build`, `npm test`) і опублікуйте.

Під час збірки файл перевіряється: `schemaVersion` має бути 1, у кожної гри мають бути `id`, `status`, `name`,
`tagline`, `customerPrices` та інші поля типу `Game`, а гра зі статусом `available` без `mock` повинна мати
`orderUrl`, що починається з `https://t.me/`. Якщо щось не так, збірка падає з назвою гри й поля.

Змінити текст, ціну пакета чи статус гри можна лише в платформі, а потім знову виконати експорт і копіювання.

Ціну запуску й підписки гри задає адмінка платформи (сторінка гри в розділі «Каталог»). Сайт бере
її двома шляхами. Під час збірки — з `games.generated.json`: щоб там були ціни з адмінки, а не з `.env`,
експорт на сервері платформи робиться з базою: `npm run export:games -- --from-db`. Після відкриття
сторінки браузер питає `/api/public/games` і підставляє актуальні ціни (`src/lib/live-prices.ts`), тож
нова ціна видно за хвилину без перезбирання. Для цього в nginx сайту потрібен блок
`location = /api/public/games` з `deploy/nginx.conf.example`. Тексти FAQ, кроків і опису для пошуку
беруть ціну зі збірки.
Руками `games.generated.json` не правте: тест платформи звіряє ціни пакетів із самою грою.

### Кнопка «Замовити»

Посилання береться з поля `orderUrl`, вручну його не збирають. Воно має вигляд
`https://t.me/<бот Кабінету>?startapp=order_<platformId>` і відкриває Кабінет у боті одразу на цій грі.
Щоб `startapp` відкривав саме Mini App, у @BotFather для бота Кабінету має бути налаштовано
Bot Settings → Configure Mini App → `https://app.klitynka.online`. Імʼя бота Кабінету (`cabinetBot`)
теж приходить з файлу; з нього сайт будує кнопку «Кабінет» у шапці й посилання у футері.

Контакт «Написати нам» — це `VITE_TELEGRAM_URL` у `.env`. Якщо його не задано або там лишилась заглушка,
береться `DEFAULT_CONTACT_URL` з `src/data/brand.ts`.

### Генетичний відбиток

Відбиток ніде не зберігається: сайт рахує його з назви гри, `dna.genre` і `dna.color`
(правило в `design/DESIGN-SPEC.md`, розділ 5; код у `src/lib/fingerprint.ts`). Зміните назву або колір,
зміниться й візерунок. Після додавання гри запустіть `npm test`: тест перевіряє, що візерунок нової гри
не повторює інший і не лежить на межі округлення (тоді він гарантовано однаковий у будь-якому браузері).
Якщо тест підкаже змінити колір, достатньо зсунути його на один відтінок.

Жанр (`dna.genre`) — один із п'яти: `slova`, `viktoryny`, `holovolomky`, `pamiat`, `druzi`
(назви для відвідувача — `src/data/genres.ts`). Від жанру залежать підпис у каталозі, чіп фільтра
(з'являється сам, щойно в жанрі є гра) і один із чотирьох кольорів відбитка (решта — колір гри, корал і
слонова кістка). Колір гри (`dna.color`) — відтінок у форматі `#rrggbb`; якщо він погано читається на
темному тлі, відбиток замість нього бере колір жанру.

### Статуси й заглушки

| Що в даних | Що бачить відвідувач |
| --- | --- |
| `status: 'available'` | «працює», кнопки «Замовити в Кабінеті» й «Пограти», ціни для гравців, калькулятор, що входить, план, картка запуску |
| `status: 'soon'` | «у розробці», механіки, за що гравці платитимуть, кнопка «Повідомити про запуск». Без цін, покупки й калькулятора |
| `mock: true` | Те саме, що `soon`, **навіть якщо помилково стоїть `available`**; сторінка не індексується й не потрапляє в `sitemap.xml` |

Справжньою гра стає в платформі: там прибирають `mock` і ставлять `status: 'available'`, а експорт додає
`orderUrl`. На сайті після нового файлу лишається хіба що додати `searchTitle` і картинку прев'ю (крок 4).

## 2. Економіка (калькулятор)

Калькулятор на сторінці гри рахує прибуток власника гри з `economics`
(логіка в `src/lib/economics.ts`, її не змінюйте). Самі числа задаються в платформі, у
`content/site/games.json`, і приходять разом з експортом:

| Поле | Що означає | Звідки брати |
| --- | --- | --- |
| `payerRate` | частка гравців, які платять хоча б раз на місяць | обережно: 0,02–0,05 |
| `arppuStars` | скільки зірок у середньому витрачає один платник за місяць | зі статистики Кабінету справжньої гри |
| `apiCostPerPayerUsd` | змінні витрати на платника, $ | для словесних ігор зазвичай 0 |

Курс виплати зірок і курс гривні лежать у `src/data/site.ts` → `RATES`.
Прогнози на сайті завжди підписані як модель, а не гарантія доходу.

## 3. Обкладинка й скріншоти

- Без файлів замість обкладинки показується генетичний відбиток гри (з назви, `dna.genre` і `dna.color`). Цього достатньо.
- Справжня обкладинка: файл 800×600 (`.webp` або `.png`) у `public/images/games/<id>/` і поле `cover`.
- Поля `theme`, `coverWord`, `demo`, `screenshots` і `channels` лишились від попереднього дизайну:
  сторінка «ДНК» їх зараз не показує, але дані збережено, якщо їх захочеться повернути.

## 4. Картинка прев'ю посилання

Коли посилання на `/games/<id>` надсилають у Telegram, під ним з'являється прев'ю:
назва бренду, заголовок, опис і картинка. Заголовок і опис сайт бере з даних гри сам.
Картинку треба покласти файлом:

1. Запустіть `npm run dev` і відкрийте `http://localhost:5173/lab/og.html`.
2. Знайдіть свою гру й натисніть «Завантажити PNG».
3. Покладіть файл у `public/og/` під назвою `<id>.png` (назва написана поруч із кнопкою).
   Або збережіть усі картинки одразу: `node lab/og-export.mjs` (при запущеному `npm run dev`, потрібен Playwright).

Якщо файлу немає, збірка попередить і візьме загальну картинку `public/og/default.png`.
Власну картинку з іншою назвою можна вказати полем `ogImage`.

У `.env` має стояти правильна адреса сайту `VITE_SITE_URL=https://klitynka.online`: Telegram завантажує картинку саме за нею.
Telegram запам'ятовує прев'ю. Щоб оновити вже показане прев'ю, надішліть посилання боту `@WebpageBot`.

## 5. Перевірка

```bash
npm run dev      # http://localhost:5173
```

- Гра з'явилась у каталозі `/games`, правильний статус і жанр.
- Блок на головній «N гра вже працює» і «ще M у розробці» порахував гру правильно (рахуються лише доступні, заглушки йдуть у «ще»).
- Сторінка `/games/<id>` відкривається; для `available` працює «Пограти», для `soon` його немає.
- Без помилок у консолі (крім попередження про заглушки, поки вони є).

```bash
npm run build    # перевірка типів + збірка + prerender
npm run preview  # перегляд готової збірки
```

Після збірки в `dist/games/<id>/index.html` має бути `<meta property="og:title" …>` з назвою гри, а адреса гри
з'являється в `dist/sitemap.xml`. Як виглядатиме посилання в Telegram, показує макет (з og-мета зібраної сторінки):

```bash
node lab/tg-preview.mjs /games/<id>     # пише lab/tg-preview.html, відкрийте його в браузері
```

## 6. Публікація

```bash
git add . && git commit -m "Нова гра: <назва>" && git push
# на сервері:
~/apps/business-kit/deploy/update.sh
```

nginx уже налаштований (`try_files $uri $uri/ /index.html`), тож нова сторінка запрацює одразу.
